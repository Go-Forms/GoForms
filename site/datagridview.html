DataGridView

The spreadsheet of a forms application: columns with captions, rows of cells, editing in place, and - bound to a BindingSource - a live view of a slice of structs that the user can add to and delete from. GoForms' grid follows System.Windows.Forms.DataGridView, and the designer builds one column by column.

At a glance

  • Columns are text, check boxes or buttons; each has its own width or sizing mode, alignment, read-only flag and visibility.
  • Cells are strings. Bound to records, each column shows one field, converted to and from its type.
  • Editing is the DataGridView gesture: click to select, click again (or just type) to edit.
  • Adding and deleting: a row for new records at the bottom, and Delete for the selected row - both with events that can say no.
  • The designer edits all of it: click a column's header on the canvas and the panel edits that column.

Each has a setter taking the column's index, which is what the designer writes: SetColumnWidth, SetColumnSizeMode, SetColumnAlign, SetColumnReadOnly, SetColumnKind, SetColumnButtonText, SetColumnHidden, SetColumnDataPropertyName. AddColumn appends one, and Column(i) gives the column itself.

A hidden column renumbers nothing

Indices always count every column, drawn or not. A hidden id column is how a row carries the key it was loaded by: CellByName(row, "id") reads it as if it were on screen. VisibleColumns() says which are drawn.

Rows and cells

SetCell and AddRow are the program speaking, so they raise no CellValueChanged - that event is for what the user typed. They raise RowsChanged, for anything that shows a count.

Check boxes and buttons

A check box column's cells are "true" or "false", drawn as a tick the user toggles with one click. A button column's cells are buttons, for the per-row actions a grid usually needs:

A button has no value to edit, so a button column is never editable, and a read-only grid's buttons still work - read-only is about values. The row for new records has no buttons: it is not a row yet.

Widths, heights, scrolling

The order of work on every layout: fixed columns take their width, fitted ones take their content's, and fill columns share what is left in proportion to their FillWeight, never below their MinWidth. A per-column mode written after the grid-wide SetAutoSizeColumnsMode overrides it for that column, which is how the designer writes them.

SetScrollBarsWhat happens when the content is bigger
ScrollBarsBothThe default: natural sizes, both scrollbars as needed.
ScrollBarsVerticalColumns are fitted into the width - fill columns absorb it, or all shrink in proportion down to their minimums.
ScrollBarsHorizontalThe grid grows as tall as its rows, as AutoSize would.
ScrollBarsNoneBoth of the above.

The designer's canvas sizes columns with the same code the running grid uses (a golden test keeps the two in step), so what you see while designing is what you get.

Editing

A grid is editable unless it, or the column, is read-only. Edits apply as they are typed: by the time the editor closes, the cell - and, on a bound grid, the record's field - already holds the text.

CellValueChanged fires once per change the user makes, with the text on either side. On a bound grid, text that does not convert to the field's type (letters in a number column) is put back as it was.

Selection

Selection is one cell. SelectionChanged fires when it moves - to another row or another column - and with Row == -1 when it is cleared. CellClick fires on every click, moved or not.

Binding to records

A BindingSource holds a list of records - a slice of structs, or of pointers to structs - and a current position, and keeps every control bound to it in step. Bound, the grid shows one row per record and each column the field its DataPropertyName names.

  • Selecting a row moves the position; moving the position (MoveNext, SetPosition) selects the row.
  • An edited cell writes its field back, converted: string, bool, every integer and float kind. Text that does not convert is put back.
  • Fields are found by name, so only exported fields can be shown.
  • A grid none of whose columns names a field shows the field with each column's title - "Name" shows Name.

Adding and deleting

With adding allowed, the grid draws one more row, marked *. The first character typed into it makes it a row: on a bound grid, a zero-valued record is appended to the slice, the typed field is set on it, its other cells show its other fields, and UserAddedRow fires. A new * row appears below. Selecting the * row moves nothing - it is not a record yet.

With deleting allowed, Delete on a selected row (not while editing) raises UserDeletingRow, removes the row and its record unless a handler cancelled, then raises UserDeletedRow:

The slice has to be given by pointer

A BindingSource given customers holds a copy of the slice header and cannot make it longer, so a grid bound to it draws no * row and AddNew returns an error. Give it &customers. An unbound grid adds and deletes plain rows either way.

Putting a grid on a form

In the designer's Controls tab, DataGridView is under Data; BindingSource is under Components - it has no place on the form, so it goes to the tray below the canvas. Click or drag either onto the form.

The grid's smart tag - the small arrow at its top-right corner - has the common tasks: dock it to fill its container, add a column, jump to the columns list, and make the columns from a type.

The columns list

One row per column, in order:

  • ⠿ - drag to reorder. The setters follow their column.
  • Caption - the header text.
  • Type - Text, Checkbox or Button.
  • Field - its DataPropertyName.
  • ⚙ - edit this column in full (below).
  • 👁 - hide or show it.
  • ⌫ - delete it.
  • + Column adds one at the end.

Below the list are the grid's own properties: columnsMode, rowsMode, rowHeight, scrollBars, frozenColumns/Rows, gridLines, showHeader, readOnly, allowUserToAddRows, allowUserToDeleteRows and dataSource. A property in bold is set in the file; ↺ beside it takes the line out again.

One column at a time

Click a column's header on the canvas - or ⚙ in the list - and the panel opens a Column group for it, above the grid's own settings. The header stays highlighted while that column is the one being edited; selecting another control lets it go.

In the panelWrites
HeaderTextThe caption in NewDataGridView(…)

DataPropertyNameSetColumnDataPropertyName(i, "Credit")

Every change is one edit of the designer file, undone by Ctrl+Z like any other, and the canvas redraws the grid with it.

Columns from a type

Columns from a Type… on the smart tag lists the structs declared in your project. Pick one - models.Customer - and the grid gets a column per exported field, captioned with the field's name and showing it: a bool field becomes a check box column. It replaces the columns the grid had; adjust them from there.

Binding in the designer

Set the grid's dataSource to a binding source of the form - the list offers the form's BindingSource components. Then each bindable control (a text box, a check box, a number box) has a (DataBindings) group: the source, and the field.

What the designer cannot do is hand the source its data - that is the program's job, in Load or wherever the data arrives: mf.bsCustomers.SetDataSource(&customers). Until then the canvas shows placeholder cells.

Traps

No * row on a bound grid

The source was given the slice by value. Pass a pointer: SetDataSource(&customers).

A column stays empty

Its DataPropertyName names no exported field of the record - check the spelling, and that the field starts with a capital letter.

Changes made in code do not show

The grid shows the records as they were when bound. After changing the slice yourself, call ResetBindings(), as in WinForms.

A typed number is put back

The text did not convert to the field's type - "12,5" into a float64. The cell goes back to the record's value.

SetCell raised no event

By design: CellValueChanged is for the user's edits, so a handler that writes cells does not call itself.

Delete removed a character, not the row

An editor was open. Enter closes it; then Delete is the row's.
